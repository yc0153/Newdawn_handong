# 검증 결과

최종 검증일 2026년 10월 11일(10월 19일 추가 검수는 아래 별도 절). P0 기능(M01·M02·S01·S02·S03·A01·A02·P01)을 로컬에서 구현하고 아래처럼 검수했다. 운영 환경(실제 Supabase 클라우드 프로젝트·배포 도메인·실제 지도 공급자)은 아직 검증하지 않았다.

## 검증 환경

- Node.js 22.22, Next.js 16.3.8 운영 빌드(`next build && next start`)와 개발 서버.
- **로컬 Supabase 동등 스택**: Docker 이미지 저장소에 접근할 수 없는 환경이어서 `supabase start` 대신 같은 구성요소를 직접 띄웠다.
  - PostgreSQL 16.15 (Supabase 기본 역할 `anon`·`authenticated`·`service_role`·`authenticator`, public 스키마 기본 권한 부여까지 재현)
  - Supabase Auth(GoTrue) v2.177.0 — 공개 가입·익명 로그인 끔
  - PostgREST 12.2.3
  - `/auth/v1`·`/rest/v1` 경로와 CORS를 처리하는 게이트웨이(Kong 역할)
  - 키는 기존 방식 JWT(anon·service_role)를 사용했다. 새 형식 키(`sb_publishable_…`·`sb_secret_…`)를 게이트웨이가 변환하는 동작은 실제 Supabase에서 확인해야 한다.
- 지도 타일: 외부 타일 서버 접근이 막혀 검수용 로컬 타일(“TEST TILE” 격자)을 사용했다. 실제 지도 공급자의 표시·출처·약관은 확인하지 않았다.
- 브라우저: Playwright 1.56 Chromium.

### 연결 검수(Next ↔ Supabase Auth·PostgREST·RLS)

- 공개 API: `no-store`, 공개 응답 4종 필드만, mode 검증.
- 등록: 201/같은 키 200/다른 내용 409, **동시 5건 → 1건**, 공개 선택 종속 422, 정밀 좌표 필드 400, 영역 밖 422, 9/10/500/501자 경계, HTML 문자열 평문 저장, 다른 출처 403.
- 빈도 제한: 같은 클라이언트 10분 5건 후 429, 성공 재시도는 미집계, 위조 `X-Forwarded-For`로 우회 불가.
- 권한(T14·X11): 익명·publishable 키로 원문 테이블·모든 RPC·내부 테이블 접근 거절, 일반 로그인·비활성 담당자는 관리자 API 403·RLS 0행·RPC 거절, `user_metadata` 조작으로 권한 획득 불가, 담당자 비활성화 즉시 다음 요청 거절.
- 검토 수명주기(T08~T11·X10): 미검토 비공개 → 요약·공개 → 상영 포함 → 공개 중 요약 수정 409 → 숨김 즉시 제외 → 재공개 시 상영 재확인 필요 → 두 담당자 동시 변경 1건만 성공 → 삭제 후 원문·요약 비움·404·이력 유지.
- 삭제 후 같은 키 재시도: 영수증만 반환, 재생성 없음(X05).
- 활성 담당자도 테이블 직접 UPDATE 불가(RPC로만 변경).

## 독립 검토에서 고친 결함

별도 검토 에이전트가 코드를 읽고 찾은 결함을 모두 수정하고 테스트를 추가했다.

1. 등록 성공 직후 화면 전환 전 재클릭으로 2건이 생길 수 있던 문제 → 성공 후 잠금 유지(E2E 추가).
2. 담당자가 PostgREST로 테이블을 직접 UPDATE하면 버전 검사·숨김 시 상영 해제·조치별 이력을 우회할 수 있던 문제 → 직접 UPDATE 권한 회수, RPC만 허용, 트리거에서도 숨김 시 상영 해제·한 번에 한 조치 강제(DB·연결 테스트 추가).
3. 공개 안내 버전이 코드 상수와 DB 설정에 이중 정의 → 서버는 형식만 검사하고 DB 현재값과 비교.
4. 플레이어 단축키: 버튼 초점에서 F가 막히던 문제, 지도 초점에서 방향키가 사례도 넘기던 문제.
5. 개발 모드(StrictMode)에서 완료 화면 번호가 사라지던 문제.

## 아직 검증하지 않은 범위

- 실제 Supabase 클라우드 프로젝트(새 형식 API 키, Auth 이메일·비밀번호 재설정 메일, advisors, 네트워크 지연).
- 실제 배포 도메인에서 쿠키·캐시·CDN·iframe(`ALLOWED_FRAME_ANCESTORS`)·신뢰 IP 헤더 동작.
- 실제 지도 공급자 타일의 한·영 가독성, 출처 표시, 약관·사용량.
- 실제 모바일 기기·스크린리더 점검(자동 검수는 Chromium의 폭·글자 크기·키보드 기준).
- 운영 수집 지역·담당자·공개 안내·보유기간은 학교 확정 전이며, 운영 DB의 `allowed_cells`는 비어 있고 `submissions_enabled`는 false다.
